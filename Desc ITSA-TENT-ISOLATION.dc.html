ITSA-TENT — การแยกข้อมูลผู้เช่า (Tenant Isolation)

สวิตช์ pooled/siloed + ที่อยู่ของข้อมูล รายผู้เช่า · โมเดล Hybrid · Mee-ERP OS

ตาราง tenant-isolation คือที่กำหนด ต่อผู้เช่าแต่ละราย ว่าข้อมูลจะถูกเก็บ ที่ไหนและแยกลึกแค่ไหน — เป็นการนำโมเดล pooled/siloed มาตั้งค่าใช้จริง

4 ฟิลด์หลัก

ฟิลด์ความหมายค่าที่เลือกได้
รูปแบบแยกข้อมูล
mode		แยกลึกแค่ไหนShared Schema = Pooled (DB เดียว แยกด้วย tenant_id) · Dedicated DB = Siloed (DB เฉพาะราย)
ฐานข้อมูล
db		backend ที่ใช้เก็บMicrosoft SQL Server · PostgreSQL · MySQL · Google Sheet
ประเภทการแบ่งพาร์ท
partition_type		แบ่งไฟล์ยังไง (เฉพาะ Google Sheet)พาร์ทฐานข้อมูลรวม (ไฟล์เดียว) · พาร์ทฐานข้อมูลแยกตามโมดูล
ปลายทางข้อมูลที่อยู่จริงของข้อมูลลิงก์ App Script (Sheet) หรือ ข้อมูลเชื่อมต่อ DB

ฟอร์มปรับตามฐานข้อมูลที่เลือก (Conditional)

ถ้าเลือก Google Sheet

  • แสดง ประเภทการแบ่งพาร์ท
  • พาร์ทรวม → ลิงก์ App Script — ALL (เดียว)
  • พาร์ทแยกตามโมดูล → ลิงก์รายโมดูล PROC · SALE · INVT · PROD · SRVC · ACCT · HRMS · ADMS · ITSA

ถ้าเลือก SQL Server / PostgreSQL / MySQL

  • ซ่อนลิงก์ App Script ทั้งหมด (รวม — ALL)
  • แสดงข้อมูลเชื่อมต่อ DB: db_host · db_port · db_name · db_schema* · db_user · db_ssl
  • *สคีมาแสดงเฉพาะ PostgreSQL / SQL Server

กลไก: เงื่อนไขแสดงฟิลด์รองรับทั้งแบบ ค่าอยู่ในชุด (OR) และ เงื่อนไขร่วม (AND) — ลิงก์ Sheet ถูก gate ด้วย db == Google Sheet AND partition_type == …

บทบาทในระบบ Hybrid: ตารางนี้เป็น "สวิตช์ pooled/siloed + ที่อยู่ข้อมูล" รายผู้เช่า — กำหนดว่า tenant ไหนอยู่ DB รวม (pooled) ไหนแยก DB (siloed) และข้อมูลไปลงปลายทางใด ทำให้ระบบให้บริการทั้งลูกค้าเล็ก (Sheet/Pooled) และลูกค้าใหญ่ (Dedicated DB/Siloed) บนแพลตฟอร์มเดียวได้ · ทุกฟิลด์ persist ลง Google Sheet ผ่าน projection/native
