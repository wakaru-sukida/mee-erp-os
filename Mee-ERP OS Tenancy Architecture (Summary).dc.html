Mee-ERP OS — สถาปัตยกรรม Multi-Tenant (สรุปการตัดสินใจ)

เอกสารสรุปแนวทาง Tenancy ที่เลือกใช้ · รวมข้อสรุปจากการพิจารณาทั้งหมด

✓ ตัดสินใจ: HYBRID (POOLED-FIRST) — เหมาะสมกับ ERP SaaS

แนวทางที่เลือก

Hybrid (Pooled-first) — เริ่มให้บริการแบบ Pooled แล้วเปิด Siloed เป็นแพ็กเกจ Enterprise โดยออกแบบ schema ให้รองรับทั้งสองแบบตั้งแต่วันแรก

Pooled
SME / ลูกค้าเล็ก-กลาง ── โตขึ้น / ขอ isolation ──▶ Siloed (DB-per-tenant)
Enterprise tier
  • Pooled: DB เดียว + tenant_id NOT NULL บนตาราง tenant-owned + Row-Level Security
  • Siloed: แยก DB/instance ต่อราย — แพ็กเกจ Enterprise สำหรับลูกค้าที่ต้อง compliance/แยกกายภาพ/ปรับแต่ง
  • Global master (geo/currency) เป็น platform-global ไม่มี tenant_id · ปรับแต่งรายเจ้าผ่าน override table

ทำไม Hybrid เหมาะกับ ERP โดยเฉพาะ

ได้อะไร

  • ข้อมูล ERP อ่อนไหว (บัญชี/HR/ลูกค้า) — ลูกค้าใหญ่บังคับ isolation ได้
  • มี tier siloed ไว้ปิดดีลองค์กร
  • pooled รองรับ SME จำนวนมากด้วยต้นทุนต่ำ

ถ้าเลือกสุดขั้ว

  • Pooled ล้วน → เสียดีล Enterprise ที่ต้องแยกข้อมูล
  • Siloed ล้วน → แพงเกินไปสำหรับ SME
  • Hybrid จึงตอบได้ทั้งต้นทุนและความเชื่อมั่น

ทิศทางการย้าย

pooled → siloed ง่าย: export WHERE tenant_id = X แล้ว restore เข้า DB ใหม่ · siloed → pooled ยาก (แต่แทบไม่มีเคสธุรกิจ เพราะเป็นการลด tier) — จึงออกแบบให้ tenant_id อยู่ในทุกตาราง tenant-owned ตั้งแต่วันแรก การใส่ทีหลังคือ migration ที่แพงมาก

สรุป tenant_id ต่อกลุ่มตาราง

กลุ่มตารางtenant_idการป้องกัน
tenant-owned
company · branch · department · transaction …		NOT NULLRLS + composite FK คู่ (tenant_id, …)
override
tenant_geo_override · tenant_currency_override		NOT NULLRLS + status
global master
country/province/district/subdistrict · currency		ไม่มีคอลัมน์ใช้ร่วมทุกผู้เช่า · อ่านแบบ global ∪ override

3 จุดที่ต้องล็อกให้ครบ

  1. ID strategy กันชนตอนแยก/รวม: ใช้ UUID หรือ id ที่ผูก tenant — ไม่ใช้ auto-increment ต่อ DB ล้วน
  2. Global master ต้องตามไปตอน export: snapshot master ทั้งชุด + override ของ tenant นั้น ไปตั้งต้น DB ใหม่ กัน FK หัก
  3. Siloed คุมต้นทุนด้วย packaging: เป็น tier ราคาสูง (Enterprise/Dedicated) เท่านั้น — ห้ามแจก siloed ให้ SME

สถานะปัจจุบันของ Mee-ERP OS

วันนี้เป็น Siloed (Single-Tenant) — แต่ละองค์กรมี deployment ของตัวเอง, ขอบเขตข้อมูล = company_id, tenant anchor ที่ตาราง company · เก็บข้อมูลบน Google Sheet จึงยังบังคับ scope ที่ชั้นแอป (ยังไม่มี RLS/composite FK ระดับ DB) เมื่อย้ายไปฐานข้อมูลจริงและทำ Pooled ค่อยเพิ่ม tenant_id เฉพาะตาราง tenant-owned แล้วเปิด RLS + composite FK
